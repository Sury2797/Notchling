# Local AI usage

`LocalAiUsageService` automatically discovers supported, read-only metadata beneath `CODEX_HOME/sessions`, `CODEX_HOME/archived_sessions` and `CLAUDE_CONFIG_DIR/projects`. Without those environment overrides, it uses `.codex` and `.claude` in the user's profile. It opens only JSONL session/transcript files in these locations. It does not open credentials, browser history or account databases, and it makes no network requests.

- **Codex:** `session_meta.payload.id` identifies the session. `event_msg.payload.type = token_count` carries `info.total_token_usage`; cumulative counters are merged once per session across repeated/copied files. Cached input and reasoning output are subsets of input/output. Provider-reported `rate_limits` supplies observed primary/secondary percentages, durations and reset timestamps when present. Quotas become stale after five minutes or a recorded reset passes. They are historical source observations, not a live account query or an authorization to use the account.
- **Claude Code:** assistant `message.usage` supplies uncached input, cache reads, cache creation and output. The input total includes those actual input components. Retransmitted/copied assistant messages are deduplicated by message ID across sessions. These transcripts do not supply subscription allowance; remaining quota is unavailable.
- **Other providers:** no adapter is implemented. Missing/unsupported records are unavailable, never zero. No token counter is converted into a subscription percentage or cost estimate.

Codex fields follow its public [protocol](https://github.com/openai/codex/blob/main/codex-rs/protocol/src/protocol.rs), including `TokenCountEvent`, `TokenUsage` and `RateLimitSnapshot`. Claude Code transcript support uses the same recognized local metadata shape as the existing explicit `CodingImporter`; it is not an account API contract. Schema changes produce missing/partial states rather than invented values. Actual user CLI records still need authorized integration validation before declaring a particular live installation verified.

The service runs filesystem discovery and parsing on a background worker, refreshes at most every 30 seconds automatically (five seconds for explicit refresh), and caches only metadata for unchanged files. It selects at most 256 recent files per provider, reads at most 8 MiB per file and 32 MiB of selected files per provider, visits at most 512 directories, and limits each line to 256 Ki characters. Partial coverage is labelled. Reparse points and UNC roots are skipped. A growing file is read only through its observed length; incomplete final writer lines are retried after an append. Deleted files are removed from totals. Read failure can retain previously measured values with an explicit stale state.

No prompts or response text enter snapshots or logs. JSONL parsing briefly reads lines to locate metadata; this must be disclosed in the application's privacy explanation. The service does not persist its metadata cache or send it outside this device.
